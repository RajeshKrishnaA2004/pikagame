## 1. What this is

A Unity 6 top-down creature-collecting game being remade **end to end**.

It started life as a Pokémon-style vertical slice (`MainMenu → Lab → Route1`,
professor, 3 starters, "PROFESSOR OXE"). That flow still exists but is
**legacy**. The remake is built around a new `Overworld` scene.

There is a design document — `Borrowed_Time_Design_Doc.docx` (workspace root) —
describing a *different*, much larger game than what is currently playable:

| Doc spec | Value |
|---|---|
| Party | 1 → max 6 creatures |
| Levels | 5 gyms, gym leader only, no normal trainers |
| Reward | after a win, pick one: new creature **or** an upgrade (max 5 upgrades) |
| Creature life | any creature used in a gym is **gone forever** when the level ends |
| Last Ember | free weak creature every gym, own slot, un-upgradable, anti-softlock |
| Types | **Flame, Tide, Leaf, Stone, Spark** (not Fire/Water/Grass) |
| Damage | `(Attack × Power / Defense) × TypeMultiplier × random(0.85–1.0)`, mult 2.0/1.0/0.5 |
| Content | ~12 original creatures + 1 evolved form each |
| Art | 16×16 pixel art, Game Boy 4-colour palette, **no outside assets**, Tilemap 8/16px |
| Audio | jsfxr (SFX) + BeepBox (music) |

**Agreed direction:** build the *engine/world layer first* (rendering, map,
zoom, minimap, gating, art pipeline) and decide the game rules once it is
actually playable. So the battle/gym systems from the doc are **not built yet**
and must not be assumed to exist.

### Script roles

| Script | Responsibility |
|---|---|
| `GameState` | Singleton. Flags, party creature types, items, `Upgrades`, `GymsCleared`. Persists to `PlayerPrefs` under prefix `bt.`. Events: `FlagChanged(string,bool)`, `RosterChanged`. |
| `CreatureType` | Enum `None/Flame/Tide/Leaf/Stone/Spark` + `CreatureTypeUtil.DisplayName/Parse` (accepts fire/water/grass/rock/ground/electric aliases). |
| `PlayerController` | 8-way move, 4-way facing. `moveSpeed 4.5`, run = Shift x1.6, `frozen` flag for dialogue. Exposes `Instance`, `Facing`, `FacingIndex` (0=Down,1=Left,2=Right,3=Up), `IsMoving`, `Cardinal` ("N"/"NE"/...), `FacingAngle`, `Teleport()`, `Face()`. Uses **legacy** `Input.GetAxisRaw`. |
| `PlayerAnimator` | Drives 16-frame sheet from `FacingIndex` + `IsMoving`. |
| `CameraRig` | Zoom band `minOrtho 2.6 / maxOrtho 12`, reference `5.4`, mouse wheel + `+`/`-`, smooth damping, clamps to `WorldBounds`, tracks mipMapBias. **Replaces `CameraFollow`.** |
| `MinimapController` | Second camera -> `RenderTexture` -> circular `RawImage`; N/S marker + compass; raises `CardinalChanged`. |
| `MapRegion` | Trigger volume; sets region name + flag on enter. |
| `RequirementGate` | Trigger + child barrier collider. Evaluates `Requirement`s; opens (disable barrier, set flag) or speaks a locked line. |
| `Requirement` / `RequirementKind` | Serializable (no asset files). Kinds: `CreatureType, CreatureTypeCount, Flag, Item, GymsCleared, Upgrades, AlwaysOpen`. Has `IsMet`, `Describe()`, `invert`. |
| `SpriteYSort` | `sortingOrder = clamp(baseOrder - round(y*step), minOrder, inf)`. **`baseOrder = 1000`, `minOrder = 1`** (see 7). |
| `HUDController` | Region banner, compass/zoom readouts, minimap caption, region canvas fade. |
| `DialogueSystem` | Refactor of `DialogueManager`; freezes player while open. |
| `ProjectSetup` (Editor) | Idempotent generator - see 6. |

## 6. Headless pipeline (how everything is rebuilt)

Menu: **Tools > PikaGame**

| Method | What it does |
|---|---|
| `ProjectSetup.EnsureFolders` | create folder tree + `.meta` |
| `ProjectSetup.ApplyImportSettings` | mipmaps **on**, aniso **8**, `Uncompressed`, bilinear, per-folder PPU (tiles 256, characters/creatures 192, props 128), feet pivots, 9-slice on `hud_panel` |
| `ProjectSetup.EnsureRenderPipeline` | assign URP to Graphics + all 6 quality levels |
| `ProjectSetup.BuildTileAssets` | PNGs -> `Tile` assets (index-mapped to terrain) |
| `ProjectSetup.BuildOverworldScene` | **generates `Overworld.unity` from scratch** |
| `ProjectSetup.CapturePreview` | renders scene + minimap cameras to `Tools/out/preview_*.png` |
| `ProjectSetup.ValidateScene` | 57 structural assertions |
| `ProjectSetup.BuildAll` | folders -> import -> URP -> tiles -> scene |

```powershell
$U = 'C:\Program Files\Unity\Hub\Editor\6000.6.4f1\Editor\Unity.exe'
$P = 'd:\project\game pika\pikagame-main'
& $U -batchmode -quit -projectPath $P -executeMethod ProjectSetup.BuildAll     -logFile $P\b.log
& $U -batchmode -quit -projectPath $P -executeMethod ProjectSetup.ValidateScene -logFile $P\v.log
```

Exit code `0` = success. Success is **only** trusted when the method itself
wrote `BUILD OK` / `VALIDATE OK` - Unity returns 0 even when `-executeMethod`
fails, so grep the log.

> WARNING: A **running Unity editor on the project holds `Temp/UnityLockfile`**
> and batch runs then exit `1` immediately. Close the editor first.

> WARNING: **`Overworld.unity` is generated.** Re-running `BuildAll` overwrites
> it - hand edits are lost. Change `ProjectSetup.cs` instead.

### Overworld scene contents
48x32 Grid (cellSize **2**, so **1 tile = 2 world units**, world = **96x64**) -
1536 painted terrain cells + **836 invisible blocker cells** on a
renderer-disabled tilemap driving a `CompositeCollider2D` (this replaced the
original single `BoxCollider2D` at `m_LocalScale 5`) - 168 props with colliders -
Player (dynamic RB, gravity 0, rotation frozen, feet box) - `CameraRig` -
circular minimap (mask + bezel + `RawImage`, 2nd camera + `RenderTexture`) -
dialogue box - 3 `MapRegion`s - 2 `RequirementGate`s.

**Terrain index order** (drives collision - water/forest/rock/wall block):
`0 grass, 1 tall grass, 2 path, 3 sand, 4 water, 5 forest, 6 rock, 7 wall, 8 floor, 9 bridge`.

**Gate ordering matters:** `STONERIDGE PASS`'s flag fires *before* gate 1 is
reached (else soft-lock), and gate 2 needs `GymsCleared >= 1` so it stays sealed
and readable.

## 7. Bugs fixed (do not reintroduce)

1. **Missing URP asset.** `QualitySettings` pointed all 6 levels at GUID
   `681886c5...` which did not exist -> silent fallback to Built-in RP. Restored
   `Assets/Settings/UniversalRP.asset` + `Renderer2D.asset`.
2. **Texture imports hostile to zoom.** mipmaps off, bilinear, aniso 1,
   compressed -> shimmer when zoomed out, smearing when zoomed in. Fixed.
3. **`map.png` at `m_LocalScale 5`** = permanent 5x upscale (1536px across
   76.8 units = 20 tex-px/unit). Removed in favour of real tilemaps.
4. **Invisible player and props** (commit `c65e2de`) -
   `SpriteYSort` computed `baseOrder(10) - round(y * 4)` while the terrain
   tilemap renders at order **0**. The world spans y = 0..64, so anything above
   y ~= 3.75 got a **negative** order and drew behind the ground. Player at
   spawn (y=13) was at -42; props at -114..-202. Fixed with `baseOrder 1000`
   (worst case 744) + a `minOrder = 1` floor, and `ValidateSorting()` now
   asserts worst-case order stays above terrain.
5. **Mixed input systems** - only safe because `activeInputHandler: 2`.

## 8. Current state and known problems

**Works:** walking with collision, zoom band, circular minimap with N/S marker,
compass/zoom readouts, region banner, requirement gates, dialogue.

**Known problems (ranked):**

1. **`map.png` is auto-classified, so the map layout is noisy** - scattered
   water rectangles and rock patches with no logic. This is probably the single
   biggest reason it "doesn't look nice". Needs a smoothing pass (kill 1-cell
   islands, fill holes, merge blobs) OR a hand-authored map.
2. **Tile scale = 2 world units** -> only ~5 tiles fill the screen vertically.
   Likely wants 1 unit/tile, but **this is deliberately undecided** pending the
   user's own art (see 9).
3. **Art is procedural placeholder** - flat blobs, visible repetition. The user
   is supplying their own assets.
4. **`lab-oke.png` has the player and professor baked into the background** -
   the old scenes draw a second player on top of a baked-in one.
5. **CanvasScaler mismatch** - MainMenu 1920x1080 vs Lab 800x600.
6. **No audio** (`Assets/Audio/Music`, `SFX` empty).
7. **No battle/gym/party systems** - the design doc's core loop is not started.
8. Preview PNGs show the **world layer only**; the HUD is Screen-Space Overlay
   and never appears in a camera RenderTexture.

## 9. Immediate next step (BLOCKED on the user)

The user is **providing their own art assets** and explicitly asked to wait.

Drop target: `Assets/Art/` (overwrite freely) or a new `Assets/Art/_Mine/`.

Needed from them:

1. **Tile pixel size** - and whether it is one uniform-grid sheet (with cols x
   rows) or one PNG per tile.
2. **Which tile is which terrain** - grass / path / water / forest / rock /
   sand / wall / bridge / floor / tall grass. Water + forest + rock + wall
   define collision.
3. **Character frame layout** - directions x frames, uniform grid.

From the pixel size the PPU is derived, which then decides **1 unit vs 2 units
per tile** - that decision is intentionally deferred, not forgotten.

Also promised regardless of the art: a **map-noise smoothing pass**, then a
re-run of `BuildAll` + `ValidateScene`.

## 10. Conventions to preserve

- **No ScriptableObjects for requirements** - `Requirement` is a plain
  `[Serializable]` class so gates survive asset GUID moves.
- **No pip / no network / no ImageMagick** - Python tooling is stdlib-only.
- **Write `.meta` files directly** when adding assets: it guarantees stable
  GUIDs and works because `Library/` has no import lock on first open.
- **Editor-only code lives in `Assets/Scripts/Editor/`** and must not leak
  Unity Editor APIs into runtime assemblies.
- **Legacy scripts stay** in `Assets/Scripts/_Legacy/` - the old scenes still
  reference their GUIDs.
- **Validate after every structural change.** The assertions exist because
  Unity exits `0` even when `-executeMethod` fails.
- **Never bake a world scale into `transform.localScale`** - it multiplies
  texture resolution loss permanently. Scale belongs in PPU + tile size.
